# Каталог фільмів з адаптивними рекомендаціями

Реалізація розділів 3–4 проєкту на основі [звіту з Requirements і Design](Movie_Catalog_Requirements_Holubtsova.docx). API побудовано на FastAPI/SQLAlchemy; клієнт — React/TypeScript; основна БД у Docker — PostgreSQL 16. Алгоритм використовує ваги взаємодій і cosine similarity з розділу 1.6 звіту.

Поточні результати розробки й тестування наведено в [звіті перевірок](reports/TEST_RESULTS_2026-11-04.md). Фінальний 30-хвилинний локальний тест завершено: P95 рекомендацій досяг цілі, P95 пошуку перевищив її; виконання NFR4.4 з п’ятьма людьми залишається непідтвердженим через відсутність учасників.

## Оновлені вимоги

Пошук підтримує повну або часткову назву й ключовий текст, один із 13 жанрів, точний рік або діапазон `year_from`–`year_to`, мінімальний агрегований рейтинг 0–10 і сортування за назвою, роком або рейтингом. Особиста оцінка залишається 1–5 відповідно до FR3.6; агрегований рейтинг каталогу відображається у шкалі 0–10. Каталог повертає 20 фільмів на сторінку. Користувач може змінити email, змінити пароль після перевірки поточного та видалити обліковий запис після введення пароля й слова `DELETE`. Видалення прибирає його оцінки, списки, історію й збережені рекомендації; агреговані рейтинги перераховуються за оцінками користувачів, що залишилися.

## Запуск на цьому комп’ютері

Застосунок налаштовано для локального запуску без Docker. Виконайте `.\start-local.ps1`: скрипт виведе адресу frontend і вибере вільний порт від 5173 (наразі `http://localhost:5174`). API документація — `http://localhost:8000/docs`. Адміністративний email і згенерований пароль збережено у `LOCAL_CREDENTIALS.txt`; файл не додається до Git. Для зупинки виконайте `.\stop-local.ps1`. Локальна база — `backend/movie_catalog.db` (SQLite). Для демонстрації синхронізації локальний запуск використовує `frontend/public/metadata.json`; у Docker можна задати власний `METADATA_URL`.

Вкладки «Увійти» та «Зареєструватися» розташовані у верхній частині сторінки. Окремі тестові акаунти адміністратора й користувача з паролями записані в `TEST_ACCOUNTS.txt` (файл ігнорується Git). Каталог містить 30 фільмів: 27 реальних позицій із локальними постерами і три авторські SVG обкладинки для демонстраційних записів. Джерела постерів наведено в `frontend/public/posters/SOURCES.md`.

## Швидкий запуск через Docker

1. Скопіюйте `.env.example` у `.env` і задайте власні `POSTGRES_PASSWORD`, `JWT_SECRET`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`.
2. Виконайте `docker compose up --build`.
3. Відкрийте `http://localhost:8080`. OpenAPI доступний за `http://localhost:8080/api/docs`.

Backend автоматично застосовує Alembic migration і додає 27 фільмів. Seed можна повторювати без дублікатів. Ще три демонстраційні записи доступні через локальну синхронізацію метаданих. Синхронізація зовнішніх метаданих вимагає `METADATA_URL` — URL JSON-масиву об'єктів з полями `title`, `year`, `external_id` та опціональними `overview`, `keywords`, `genre_ids`, `actors`, `directors`, `poster_url`. Для постера можна вказати HTTPS URL або локальний шлях `/posters/...`.

Для розгортання за межами локальної машини перед nginx слід налаштувати HTTPS/TLS 1.2+; контейнерний приклад відкриває HTTP лише для локальної демонстрації.

## Локальна розробка

Потрібні Python 3.12 і Node.js 20+.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
cd backend
..\.venv\Scripts\alembic.exe upgrade head
..\.venv\Scripts\python.exe seed.py
..\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

В окремому терміналі:

```powershell
cd frontend
npm install
npm run dev
```

Локально за замовчуванням використовується SQLite для розробки; для PostgreSQL задайте `DATABASE_URL=postgresql+psycopg://...`. Адміністратор створюється скриптом seed лише коли задано `ADMIN_EMAIL` та `ADMIN_PASSWORD`.

## Тести

```powershell
cd backend
..\.venv\Scripts\python.exe -m pytest -q
..\.venv\Scripts\python.exe -m coverage run --branch --source=app.recommendation,app.interactions -m pytest -q
..\.venv\Scripts\python.exe -m coverage report -m
```

Для навантажувального тесту використовується окрема база з 20 000 фільмів та 20 тестових акаунтів (`backend/loadtest_seed.py`). Скрипт `backend/performance_check.py` приймає файл із 20 токенами, працює 1800 секунд і записує P95, помилки та контроль безперервності у JSON. Локальний запуск наведено в `tools/run_loadtest.ps1`; він обмежує сервер двома логічними процесорами. Під час тесту `backend/persistence_check.py` перевіряє 80 змін і їхнє повторне читання. Робочий каталог при цьому не змінюється. Показники на SQLite/Windows слід відрізняти від цільового середовища PostgreSQL 16 на 2 vCPU/4 GB RAM.

Для NFR4.4 потрібні 5 реальних учасників: після входу кожен має знайти фільм, додати його до Watchlist, оцінити та відкрити рекомендації. Потрібно зафіксувати успіх і час кожної дії. Ціль — не менше 80% успіхів і середній час кожного сценарію до 60 секунд. `tools/verify_five_ui_sessions.cjs` перевіряє ці дії автоматично у п’яти браузерних сесіях; це технічна перевірка, не дослідження з людьми.

Поточні результати для оновлених вимог наведено в [звіті від 4 листопада](reports/TEST_RESULTS_2026-11-04.md). Браузерну перевірку пошуку й керування профілем можна повторити скриптом `tools/verify_updated_requirements.cjs` після запуску локального застосунку. Новий вигляд, вкладки входу, постери, оцінювання й мобільну версію перевіряє `tools/verify_visual_refresh.cjs`.

## Архітектура

- `backend/app/main.py` — REST маршрути, валідація параметрів, доступ за ролями.
- `backend/app/catalog.py` — пошук і обмежений кеш сторінок із очищенням після змін каталогу й оцінок.
- `backend/app/interactions.py` — поточний стан rating/Favorite/Watchlist/watched та історичні UserInteraction в одній транзакції.
- `backend/app/recommendation.py` — ознаки фільмів, зважений профіль, cosine, Top-K, cold start, пояснення і similar.
- `backend/app/models.py` — сутності з design schema; `backend/alembic/versions` — початкова міграція.
- `frontend/src/App.tsx` — каталог, пошук, деталі, особисті дії, рекомендації та адміністративний інтерфейс; `frontend/src/style.css` — адаптивний вигляд.

Паролі хешуються bcrypt, access tokens мають термін дії 8 годин, logout відкликає токен. Персональні дані та адміністративні маршрути перевіряють токен на сервері.
